# inFold iOS & Android apps

The App Store and Google Play apps are the **same React app** as
app.getinfold.app, wrapped with [Capacitor 8](https://capacitorjs.com).
One codebase covers the web, iOS and Android. Supabase, the Vercel `/api`
routes and the Supabase edge functions serve all three.

```
src/            React app (shared by web + iOS + Android)
ios/            Xcode project (generated by Capacitor, then customised)
android/        Android Studio project (generated by Capacitor, then customised)
assets/         Source images for app icons and splash screens
capacitor.config.json
```

---

## 1. What changed for the apps (and why)

Nothing changed for web users. Each item below only takes effect inside the
iOS or Android app.

| Area | Web (unchanged) | Inside the apps |
|---|---|---|
| `/api/*` calls | relative URLs | `https://app.getinfold.app/api/*` (`src/lib/platform.js → apiUrl`); the API routes allow the app origins via CORS (`api/_native.js`) |
| Push notifications | Web Push (VAPID) + service worker | Firebase Cloud Messaging → APNs / Android (`useNativePushNotifications.js`, table `native_push_tokens`). `send-push` and both reminder crons deliver to both |
| Tapping a notification | service worker opens the URL | `NativeBridge.jsx` navigates to the same URL |
| Stripe checkout and billing portal | full-page redirect | opens the in-app browser sheet; Stripe returns via `infold://` (`api/native-return.js`) |
| Facebook page connection | popup window | in-app browser sheet, result passed back via `infold://oauth-complete` |
| Signup confirmation and password-reset emails | link back to the site | link goes to a bounce page that reopens the **app** with the session, so signup details saved on the phone aren't lost |
| Share buttons and copy link | Web Share / clipboard | native share sheet / clipboard, sharing `https://app.getinfold.app/...` links (never `capacitor://`) |
| "Near me" in the parish directory | browser geolocation | native location permission (`src/lib/nativeShims.js`) |
| Links that open in a new tab (Terms, parish websites) | new tab | in-app browser sheet, so forms aren't lost |
| "Add to Home Screen" prompt, service worker and update banner | as before | not used. The app is updated through the stores |
| Status bar and notch | n/a | `html.cap-native` CSS in `src/index.css` |
| Android back button | n/a | goes back, or exits from the first screen |

**New feature for every platform: blocking users.** Apple guideline 1.2 and
Google Play's UGC policy require it for social apps.
- Post "…" menu → **Block user**. Profiles have a **Block / Unblock** button.
  Settings → **Blocked users** lets people unblock.
- The database enforces blocking (`supabase/migrations/028_user_blocks.sql`):
  posts, comments, prayer requests, group chat, DMs and notifications from
  blocked users are hidden, and blocked users can't DM the blocker. Existing
  policies weren't modified; the migration only adds *restrictive* policies.

### 2.1 Accounts (you)
- [ ] **Apple Developer Program**: developer.apple.com, $99/yr. Enroll as an
      organization if inFold has a legal entity (needs a D-U-N-S number).
      The store listing then shows the organization's name.
- [ ] **Google Play Console**: play.google.com/console, $25 one-time.
      New *personal* accounts must run a closed test with **12+ testers for
      14 days** before production. Organization accounts are exempt.
- [ ] **Firebase project** (free): console.firebase.google.com → Add project.

### 2.2 App identifiers
The bundle ID / package name is **`app.getinfold`** (set in
`capacitor.config.json`, the Xcode project and `android/app/build.gradle`).
It **can't be changed after the first store upload**. If you want a different
one, change it in all three places before uploading.

### 2.3 Firebase (push notifications)
1. Firebase → Project settings → **Add app → iOS**, bundle ID `app.getinfold`.
   Download **GoogleService-Info.plist**.
2. **Add app → Android**, package `app.getinfold`. Download **google-services.json**.
3. Apple Developer → Keys → **+** → enable *Apple Push Notifications service
   (APNs)* → download the `.p8`. Firebase → Project settings → Cloud Messaging →
   Apple app → upload that APNs key (with its Key ID and your Team ID).
4. Firebase → Project settings → Service accounts → **Generate new private
   key**. That JSON is the server credential:
   - Vercel → Settings → Environment Variables → `FIREBASE_SERVICE_ACCOUNT` =
     the whole JSON on one line (used by the reminder crons).
   - Supabase: `supabase secrets set FIREBASE_SERVICE_ACCOUNT="$(cat key.json)"`
     (used by `send-push`). Then redeploy: `supabase functions deploy send-push`.
5. For local builds, put the two config files at
   `ios/App/App/GoogleService-Info.plist` and `android/app/google-services.json`
   (both are git-ignored). CI injects them from secrets (§2.7).

The app still runs without Firebase config, but push notifications stay off.

### 2.4 Supabase
- [x] New migrations `027_native_push_tokens.sql` and `028_user_blocks.sql`: **applied to production on 2026-10-12**
- [ ] Auth → URL Configuration → **Redirect URLs**: add
      `https://app.getinfold.app/api/native-return**`
      Without it, confirmation and reset emails from the app fall back to the
      site URL.

### 2.5 Vercel
- [ ] `FIREBASE_SERVICE_ACCOUNT` (see §2.3).
- [ ] After your first iOS / Android builds, fill in the two placeholder files
      under `public/.well-known/` so `https://app.getinfold.app/...` links
      open the app:
  - `apple-app-site-association`: replace `APPLE_TEAM_ID` with your 10-character
    Team ID (Apple Developer → Membership).
  - `assetlinks.json`: replace `PLAY_APP_SIGNING_SHA256_FINGERPRINT` with
    Play Console → your app → Setup → **App signing** → SHA-256 fingerprint.

### 2.6 Android release signing (you, once, keep it safe forever)
```bash
keytool -genkeypair -v -keystore communio-upload.jks -alias communio \
  -keyalg RSA -keysize 2048 -validity 10000
```
Store the `.jks` file and its passwords in a password manager (1Password). For
local release builds, create `android/keystore.properties` (git-ignored):
```
storeFile=/absolute/path/to/communio-upload.jks
storePassword=...
keyAlias=infold
keyPassword=...
```
Turn on **Play App Signing** when you create the app in Play Console. Google
then holds the real signing key, and a lost upload key can be reset.

### 2.7 GitHub Actions secrets (builds without a Mac)
Repo → Settings → Secrets and variables → Actions:

| Secret | What |
|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_STRIPE_PUBLIC_KEY` | same values as Vercel |
| `GOOGLE_SERVICE_INFO_PLIST` | full contents of GoogleService-Info.plist |
| `GOOGLE_SERVICES_JSON` | full contents of google-services.json |
| `APPLE_TEAM_ID` | 10-character Team ID |
| `APPSTORE_API_KEY_ID`, `APPSTORE_API_ISSUER_ID`, `APPSTORE_API_KEY_P8_BASE64` | App Store Connect → Users and Access → Integrations → **App Store Connect API** → new key with *App Manager* role; base64 the `.p8` (`base64 -w0 AuthKey_XXX.p8`) |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 communio-upload.jks` |
| `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | from §2.6 |

**The first Play upload must be manual:** download the `.aab` artifact from a

## 3. Building

### Without a Mac (recommended for you): GitHub Actions
- Every push builds and tests everything (`.github/workflows/mobile.yml`).
- **Android test build:** open the workflow run → Artifacts →
  `infold-android-debug-apk`. Install it on any Android phone (allow
  "install unknown apps").
- **Store builds:** Actions → *Mobile apps* → **Run workflow** → tick
  **release**. iOS goes to TestFlight. Android goes to Play internal testing,
  or is attached as an `.aab` artifact.
  Build numbers come from the run number automatically.

### On your Windows PC (Android only)
1. Install [Android Studio](https://developer.android.com/studio). It includes
   the SDK and Java.
2. `npm run mobile:android` builds the web app, copies it into the Android
   project and opens Android Studio. Press ▶ to run on an emulator or a
   USB-connected phone.

### On a Mac (iOS), if you ever have one
`npm run mobile:ios` opens Xcode. Select your team under Signing &
Capabilities, then press ▶.

### After changing web code
`npm run mobile:build` (= `vite build && cap sync`) copies the new build into
both native projects. CI does this automatically.

### Icons and splash screens
These are generated from the brand cross in `scripts/generate-app-assets.mjs`.
To change them, edit that script or drop your own 1024×1024 PNGs into
`assets/`, then run `npm run mobile:assets`.

## 4. Testing before launch

### Automated
- `npm test`: unit tests for the native glue (URL handling, CORS, Stripe
  return URLs, deep links, push format, notification routing). These run in
  CI on every push.
- `npm run test:e2e`: Playwright drives the app in a phone-sized browser.
  - `tests/e2e/public.spec.js` covers signed-out screens, the login error and
    redirects.
  - `tests/e2e/app.spec.js` signs in with test accounts and opens every main
    screen. It creates, opens by link, likes, comments on and deletes a post,
    then blocks and unblocks a user (needs migration 028). Set
    `E2E_EMAIL`, `E2E_PASSWORD`, `E2E_EMAIL_2`, `E2E_PASSWORD_2` and
    `SUPABASE_SERVICE_ROLE_KEY`.
- **Real Android app** (emulator or USB phone with the debug build running):
  `node tests/native/android-smoke.mjs` runs sign-in, every tab, the server
  connection, clipboard and the back button.
  `node tests/native/android-location.mjs` tests the "Near me" permission
  and the map.
- CI builds the iOS app (simulator) and the Android app (debug APK) on every push.

### Android emulator on this PC
The Android SDK is installed at `%LOCALAPPDATA%AndroidSdk`, with Java
at `%LOCALAPPDATA%Androidjdk`, and there's an emulator named
`communio_test` (Pixel 7, Android 15). Install Android Studio to get a
visual emulator and one-click runs; it reuses the same SDK.

### Beta testers
- **iOS: TestFlight.** After a release run, App Store Connect → TestFlight.
  Internal testers (up to 100 App Store Connect users) get builds immediately.
  External testers (up to 10,000, by email or a public link) need a quick
  one-time Beta App Review, usually under 24 hours.
- **Android: Play testing tracks.** Internal testing (up to 100, instant) →
  Closed testing (the 12-testers-for-14-days requirement for new personal
  accounts) → Production.

## 5. Releasing updates

| Kind of change | What to do | Review time |
|---|---|---|
| Web-only (Vercel) | deploy as usual; the apps' `/api` and Supabase changes are live immediately | none |
| App screens / UI / logic (`src/`) | bump `version` in package.json, `MARKETING_VERSION` (Xcode) and `versionName` (build.gradle); run the release workflow; submit in both consoles | Apple usually ~24h, Google hours to ~2 days |
| Native config / plugins / permissions | same as above | same |

The app bundles a copy of the web code, so **UI changes reach app users only
through a store release**. If that becomes painful, add over-the-air updates
([Capgo](https://capgo.app) or Ionic Appflow Live Updates). They push `src/`
changes straight to installed apps and are allowed by both stores for web
content.

**Database changes are shared.** A migration that breaks old app versions
breaks everyone who hasn't updated, so keep migrations backward-compatible.

## 6. Store questionnaires

### App Store "App Privacy"
Matches `ios/App/App/PrivacyInfo.xcprivacy`. All of the following are linked to
the user, used only for App Functionality and not used for tracking: Name,
Email, User ID, Photos, Other user content, Emails or text messages (DMs),
Device ID (push token). Coarse Location is not linked and not stored.

### Google Play "Data safety"
The same data types; data is encrypted in transit; users can delete their
account in-app (Settings → Delete account). Provide a web deletion URL too
(Play requires one): e.g. `https://app.getinfold.app/contact`.

### Content rating
User-generated content and user-to-user messaging: answer **yes** to both.

### Account deletion
In-app deletion exists (Settings), as Apple guideline 5.1.1(v) requires.

## 7. Issues found and fixed during testing

- The "Make a Gift" / Support the Mission feature was removed entirely. Old
  `/premium` links redirect home.
- Shared post links now open the post (`/post/:id`).
- Notification taps (in-app and push) open the right screen: likes, comments
  and announcements open the post; parish-admin alerts include the parish.
  Announcement taps used to go to a "Not found" page.
- On iPhone Safari, the "Add to Home Screen" banner covered the sign-in form.
  It now shows only to signed-in users, never on sign-in, sign-up or legal
  screens, and stays compact until tapped.
- Android: status-bar icons were invisible on older phones (fixed). "Near me"
  location now falls back to GPS when there's no Wi-Fi or cell location.
- The readings API's cached responses were blocked inside the apps (fixed).
- Map tiles: OpenStreetMap works inside the apps (tested). Set
  `VITE_MAPBOX_TOKEN` to switch to Mapbox automatically if traffic grows.

Set these in Vercel so the website's install banner sends phone visitors to
the stores instead of "Add to Home Screen":
`VITE_IOS_APP_STORE_URL`, `VITE_ANDROID_PLAY_STORE_URL`.
